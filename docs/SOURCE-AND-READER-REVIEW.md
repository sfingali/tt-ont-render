# Seven guides: source and editorial review

Review date: 13 September 2026. Baseline: merged reader commit `30d7414169bf15a8eb744dd7440aca50568f0487`. The original ontology records remain pinned to `021e23d9c23d1fba5e5b7fdbc6400e6be1c949a2`.

## Outcome

The seven guides now explain more of the work a reader previously had to infer. Names have introductions, technical terms have local explanations, and several headings and time labels have been corrected. This pass changes editorial content and documentation; it requires no new ontology, schema fields or renderer features.

Source verification is **partial**. Accessible creator interviews and a screenplay corroborate specific claims. No complete film or episode viewing was performed in this pass. All seven `sourceReview` and `readerReview` values remain `pending`. A screenplay draft, a producer’s synopsis and an ontology record are different kinds of evidence; none automatically certifies the released work.

The reader review here is an **editorial walkthrough**, conducted by the assistant against the actual guide text. There have been **zero participant sessions**. The [reader study kit](READER-STUDY.md) contains the protocol, questions and answer criteria for those sessions. Its answers are editorial expectations to check, not participant responses or evidence of factual accuracy.

## Completing the source review

For each guide, a reviewer with access to the stated film or episodes should watch the targeted scenes, then inspect the whole scoped strand for omitted qualifications. Record edition/cut, viewing date, reviewer, scene description and time range (or episode plus time range). A timecode without an edition is insufficient.

Check every event, premise, ending, comparison, connection and alternate view—not just newly edited sentences. Keep notes as ordinary Markdown under this document or in a linked review record. No new status vocabulary or evidence database is needed.

Resolve contradictions in the prose. If a claim remains disputed, narrow it or state the uncertainty to readers where it matters. Only then change that guide’s existing source-review flag. The untouched migration ledgers describe the initial adaptation; stable event IDs in this pass preserve their references.

## Reader review and release

Run the [study kit](READER-STUDY.md) with actual participants unfamiliar with the ontology. Source accuracy and comprehension are separate checks. A guide that is easy to repeat can still be wrong; a factually correct guide can still confuse readers.

The kit has no results yet. Do not infer human comprehension from validation, an assistant walkthrough or a generated response. Release also still requires the browser, assistive-technology and print checks in [the implementation contract](READER-DESIGN.md#acceptance-and-release-checks).
